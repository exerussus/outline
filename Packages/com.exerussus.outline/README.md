# Exerussus Outline

Аутлайн для URP на Render Graph. Контур строится в экранном пространстве по полю расстояний (Jump Flood), а не раздуванием меша: нет разрывов на жёстких рёбрах, ширина от 1 до 256 px, затухание задаётся кривой.

## Возможности

- Внешний контур с кривой затухания, ширина в пикселях или в мировых единицах.
- Внутренний контур, заливка силуэта, rim (френель).
- Отдельный стиль для перекрытой части: скрыть, как видимую или с тинтом и бегущей штриховкой.
- Паттерны: полосы, точки, сетка, клетка, скан-линии, шум, соты. Пространство: экран, объект или поверхность объекта/мира.
- Анимация: пульс альфы и ширины, шум, плавное появление и исчезновение.
- Эффекты свечения: градиент цвета по ширине и по контуру, волны, бег по контуру, огонь, электричество, искры.
- Эффекты заливки: сканер, растворение со светящейся кромкой, текстура заливки.
- Свои текстуры: маска паттерна и текстура заливки.
- Прозрачность и маскировка: объект скрывается из основного прохода камеры, на его месте — фон за ним с искажением и преломлением у края и сам объект с заданной непрозрачностью.
- Группы: объекты одной группы образуют общий силуэт. Между группами действует приоритет: свечение группы с большим приоритетом рисуется поверх силуэта соседней, с меньшим — мягко гаснет у его края; цвета на стыке смешиваются.
- Альфа-клип и прозрачные материалы: текстура и порог берутся из материала (URP Lit/Unlit, `_MainTex`/`_Color`, glTFast).
- Сглаживание края силуэта: MSAA-маска, край с субпиксельной точностью.
- Совместим с GPU Resident Drawer.
- Отладочные виды и статистика кадра.

## Требования

- Unity 6000.6, URP 17.6 (Render Graph).
- Проверено на Windows, Direct3D 11. WebGL2 предусмотрен настройками, но не проверялся.
- Подсвечиваются только `MeshRenderer` и `SkinnedMeshRenderer`.
- Кадр не больше 4095 px по каждой стороне.

## Подключение

1. Добавить фичу в рендерер: меню **Exerussus → Outline → Подключить к рендерерам URP**. Команда добавляет `OutlineRendererFeature` во все Universal Renderer Data в `Assets`. Вручную: Universal Renderer Data → Add Renderer Feature → Exerussus Outline.
2. Создать стиль: **Create → Exerussus → Outline → Style**.
3. Включить подсветку кодом или компонентом `OutlineTarget`.

## Использование

```csharp
using Exerussus.Outline;

// показать
var handle = OutlineApi.Show(gameObject, style, OutlineOptions.InGroup(group: 1, fadeIn: 0.15f));

// изменить
handle.SetStyle(otherStyle);
handle.SetStyle(otherStyle, 0.3f); // плавно за 0.3 с
handle.FadeTo(0.5f, 0.2f);

// убрать
handle.FadeOutAndHide(0.2f);
```

`OutlineTarget` — компонент для сцены: пока он включён, объект подсвечен. Работает и в редакторе.

### OutlineFx — временные эффекты

Эффект запускается, отыгрывает анимацию и снимается сам.

```csharp
OutlineFx.DissolveOut(enemy, 0.6f, onComplete: () => enemy.SetActive(false)); // растворить; объект остаётся скрытым
OutlineFx.DissolveIn(enemy, 0.6f);                                             // проявить; по окончании эффект снят
OutlineFx.Pulse(item);                                                         // одна вспышка подсветки
OutlineFx.Flash(item, new Color(2f, 2f, 2f, 0.8f));                            // засветка объекта
OutlineFx.Restore(enemy);                                                      // сразу снять всё и показать объект
```

| Член | Назначение |
|---|---|
| `DissolveOut(go, duration, style, onComplete)` | Растворение. После окончания объект скрыт камерой и ничего не стоит, пока не вызван `DissolveIn` или `Restore`. |
| `DissolveIn(go, duration, style, onComplete)` | Проявление из растворённого состояния (или полная анимация появления видимого объекта). По окончании запись снята. |
| `Pulse(go, style, duration, rise, onComplete)` | Подсветка style нарастает за долю `rise` длительности и гаснет. |
| `Flash(go, color, duration, onComplete)` | Короткая засветка цветом (HDR, альфа — сила). |
| `Restore(go)`, `IsDissolved(go)` | Снять эффекты сразу; проверить растворённое состояние. |

`style` у растворения задаёт кромку и шум (`dissolveScale`, `dissolveEdgeWidth`, `dissolveEdgeColor`, `patternSpace`); без него — встроенный. Растворение прерывается и разворачивается с текущего места: `DissolveIn` посреди `DissolveOut` начнёт с достигнутой доли. Пульс и вспышка идут в слое 1 (`OutlineFx.OverlayLayer`) — поверх обычной подсветки, которая остаётся на месте; слой можно передать параметром. Растворение — эффект объекта в верхнем слое: пока оно идёт, подсветки объекта в других слоях не рисуются, растворённый объект не рисуется нигде.

### OutlineApi

| Член | Назначение |
|---|---|
| `Show(GameObject, style[, options])` | Подсветить рендереры объекта (по умолчанию вместе с детьми). |
| `Show(Renderer, style, options)` | Подсветить один рендерер. |
| `Show(IReadOnlyList<Renderer>, style, options)` | Подсветить набор рендереров. |
| `Hide(handle)`, `HideAll()` | Снять подсветку. |
| `SetStyle`, `SetGroup`, `SetPriority` | Изменить параметры живой подсветки. |
| `SetStyle(handle, style, t)`, `IsStyleBlending` | Плавная смена стиля: цвета, ширины, кривые, градиенты и параметры эффектов смешиваются; тип паттерна, режим перекрытого и текстуры переключаются на середине. Обратная смена посреди перехода продолжает его с той же точки. |
| `SetFade(handle, v)`, `FadeTo(handle, v, t)`, `FadeOutAndHide(handle, t)` | Непрозрачность и плавные переходы. |
| `IsAlive(handle)`, `HasAny`, `AliveCount` | Состояние. |
| `MaxEntries` | Лимит одновременных подсветок: 63. |

У `OutlineHandle` те же методы экземпляра. Хэндл версионный: после `Hide` его методы ничего не делают.

Если рендерер входит в несколько подсветок одного слоя, рисуется последняя. После её снятия рисуется предыдущая. Подсветки разных слоёв рисуются одновременно, одна поверх другой.

### OutlineOptions

| Поле | Значение |
|---|---|
| `group` | Группа. Одна группа — общий силуэт. |
| `priority` | Добавка к приоритету стиля. |
| `alphaMode` | `Auto` — по материалу, `ForceClip` — всегда клипать по `alphaThreshold`, `Ignore` — силуэт по мешу. |
| `alphaThreshold` | Порог для `ForceClip`. |
| `includeChildren`, `includeInactive` | Сбор рендереров для `Show(GameObject)`. |
| `fadeIn` | Длительность появления, с. |
| `layer` | Слой 0–3 (`OutlineApi.MaxLayers`). Слои рисуются независимо и накладываются по порядку: 1 поверх 0. Группы, приоритеты, стыки и владение рендерером — внутри слоя. Каждый непустой слой — свой проход маски, поля и композита. `OutlineOptions.InLayer(layer, group, fadeIn)`. |

### Эффекты

Каждый эффект выключен при нулевой силе и ничего не стоит.

- **Свечение.** Градиент по ширине задаёт цвет от края (t = 0) к внешней границе; его альфа умножается на кривую. Градиент по контуру окрашивает свечение по углу вокруг центра объекта. Бег по контуру тоже строится по углу, поэтому на сильно вогнутых формах штрихи неравномерны. Огонь и дрожание края увеличивают дальность поля: запас на них учитывается автоматически.
- **Заливка.** Сканер, растворение и текстура заливки строятся в пространстве паттерна (`patternSpace`): в `Screen` размеры в пикселях, в остальных — в единицах мира или объекта. С `dissolveByFade` растворение заменяет обычное затухание внутренних слоёв: появление и `FadeOutAndHide` «проедаются» шумом.
- **Текстуры.** Все текстуры стилей в кадре копируются в общий массив 256×256×16 с мипами. Копирование — только когда текстура появилась впервые. Текстура приводится к квадрату; если изменить её пиксели, в массиве останется старая версия, пока слот не освободится. Для паттерна используется яркость × альфа, для заливки — цвет и альфа.

### Прозрачность и маскировка

Со `seeThrough` рендереры подсветки перестают рисоваться основным проходом камеры: в Play — через `ShadowsOnly` (тень остаётся, если `seeThroughShadows`), в редакторе и без тени — через `forceRenderingOff`. Свойства возвращаются, как только подсветка снята, погасла или стиль сменился. Фича копирует цвет камеры в области кропа и рисует на месте объекта фон со смещением: шум (`distortion`) и линза у края (`refraction` на глубину `refractionWidth`). Поверх — сам объект его материалами (проход `UniversalForward`) с непрозрачностью `objectOpacity`: 0 — маскировка, 0.2–0.5 — стекло. Остальные слои стиля (заливка, rim, внутренний контур, свечение) накладываются сверху.

`fade` работает как переход: при fade → 0 объект возвращается к полной непрозрачности и без искажения, поэтому `Show(..., fadeIn)` и `FadeOutAndHide` плавно уводят объект в маскировку и обратно.

Ограничения: фон — это то, что камера нарисовала за объектом, поэтому прозрачные объекты за ним и эффекты после пост-обработки в нём не участвуют; объект, скрытый маскировкой, не пишет глубину, и SSAO/декали его не видят.

### Пространство паттерна

| `patternSpace` | Поведение |
|---|---|
| `Screen` | Паттерн неподвижен относительно кадра, период в пикселях. |
| `Object` | Паттерн привязан к центру объекта на экране, период в мировых единицах. Следует за перемещением объекта и камеры, масштабируется с расстоянием, поворачивается вместе с объектом вокруг оси взгляда. Ничего не стоит сверх экранного. |
| `SurfaceObject` | Паттерн нанесён на поверхность в координатах объекта: проекция по доминирующей оси нормали, как у кубической развёртки. Поворачивается и масштабируется вместе с объектом. |
| `SurfaceWorld` | То же в мировых координатах: паттерн неподвижен в мире. |

Что выбрать для заливки текстурой: `Screen` и `Object` зависят от камеры (текстура скользит по граням при облёте), `SurfaceObject` едет вместе с объектом, `SurfaceWorld` стоит в мире — объект движется сквозь неё.

В режимах `Surface*` на поверхность ложатся заливка и внутренний контур; свечение снаружи силуэта строится как в `Object`. Пока в кадре есть такая запись, пишутся координаты развёртки поверхности (RG half-float, 4 байта на пиксель): без сглаживания — второй целью маски, со сглаживанием — отдельным проходом без MSAA по рендерерам этих записей (вторая цель MSAA-маски на встроенных GPU стоила ~0.75 мс). Для `SurfaceWorld` далеко от начала координат точность half-float падает, и мелкий паттерн начинает дрожать.

| `objectColor` | Simple | Чем рисуется сам объект в режиме прозрачности: упрощённое освещение по текстуре и цвету материала или исходный материал (точнее, но может не рисоваться с GPU Resident Drawer). |
| `debugView` | None | Mask / Seeds / Distance. |
| `surfaceDiag` | None | Диагностика для бенчмарка: отключает чтение или запись координат поверхности, либо включает прежний путь через вторую цель MSAA-маски. Картинка без чтения и без записи неверная. |
| `renderInSceneView` | вкл | Рисовать в Scene View. |

`OutlineRendererFeature.Stats` возвращает статистику последнего кадра игровой камеры:
- число записей и вызовов отрисовки;
- размер и масштаб поля, долю кропа, число проходов;
- стоимость поля и бюджет, число сэмплов маски;
- время записи на CPU.

### Авто-масштаб поля

Масштаб выбирается из ступеней 1, 0.75, 0.5, 0.375, 0.25: берётся наибольший, при котором стоимость не превышает бюджет. Стоимость — пиксели поля внутри области кропа × число проходов (проход с внутренним контуром считается за два). Оценка не зависит от GPU-таймеров и одинаково работает на всех платформах. Мелкие объекты получают полное разрешение, крупные и широкие свечения — пониженное.

Уменьшение масштаба происходит сразу, как только текущий превышает бюджет на 10%. Увеличение — после 30 кадров подряд, когда больший масштаб укладывается в бюджет.

## Как это работает

1. **Маска.** Подсвеченные рендереры рисуются по одному в RGBA8. В канал R пишется id записи, в G — rim, в B — видим ли пиксель относительно глубины сцены. Альфа-клип выполняет материал-двойник маски. Со сглаживанием маска рисуется в MSAA-цель, а резолв записывает в A долю покрытых сэмплов.
2. **Поле расстояний.** Сиды — граничные пиксели силуэта: у них есть соседний пиксель пустой или из другой группы. Координаты сидов хранятся в пикселях кадра, поэтому поле в пониженном разрешении даёт расстояния с точностью кадра. Внешнее поле взвешено по ширине и приоритету записи. Внутреннее поле считается только на последних шагах, на дальность внутреннего контура. При поле ниже ×1 сиды редкие, поэтому у края композит уточняет расстояние по соседним сидам: край считается ломаной через два ближайших.
3. **Композит.** Кривые, заливка, rim, паттерны, перекрытие, анимация и смешение на стыке накладываются в цвет камеры. Выход premultiplied. Покрытие граничного пикселя сдвигает край на долю пикселя, а частично покрытый пиксель смешивает заливку со свечением.

## Производительность

Замер на Intel UHD (i5-1035G1), Direct3D 11, в редакторе: кадр 1226×689, 17 подсветок, кроп — 20% кадра. В таблице — прирост времени кадра к выключенной фиче (14.3 мс, дрейф за прогон 0.04 мс).

| Режим | Масштаб | Стоимость | мс |
|---|---|---|---|
| авто (по умолчанию) | ×0.5 | 385k | 1.7 |
| ×1 | ×1 | 1884k | 4.9 |
| ×1 + JFA+1 | ×1 | 2227k | 5.7 |
| ×0.75 | ×0.75 | 963k | 3.1 |
| ×0.25 | ×0.25 | 75k | 1.0 |
| авто без scissor | ×0.5 | 385k | 2.2 |
| авто без кропа | ×0.25 | 370k | 2.1 |

Таблица снята в версии 0.2.0, без сглаживания края. С настройками по умолчанию (авто-масштаб, сглаживание ×4, мягкий стык) на той же сцене: +3.3 мс. Из них сглаживание ×4 — около 1 мс (×2 — 0.7, ×8 — 1.7), мягкий стык — около 0.5 мс. Без scissor и кропа резолв идёт по всему кадру и стоит дороже.

Витрина бенчмарка (0.4.0): прирост к кадру той же сцены без подсветки, мс, при 1, 3 и 21 подсвеченном объекте.

| Стиль | 1 | 3 | 21 |
|---|---|---|---|
| Hover (тонкий контур) | 2.7 | 2.3 | 2.5 |
| Selected (контур + внутренний) | 2.8 | 3.0 | 4.0 |
| Toon, Hatched, Rainbow | 2.3–3.1 | 2.2–3.1 | 1.3–1.7 |
| Fire, Sonar, Cloak | 2.9–3.1 | 3.1–3.5 | 2.4–2.9 |
| Паттерн на поверхности | ~4.2 | ~4.2 | 4.2–5.0 |
| Растворение (`OutlineFx`) | 3.7 | 3.7 | 4.3 |
| Selected + пульс (2 слоя) | — | 4.5 | — |

Цена почти не растёт с числом объектов: работа идёт по площади на экране, авто-масштаб держит поле в бюджете. Запись на CPU — около 15 мкс на подсветку. Постоянная часть — около 1.3 мс на слой без сглаживания и 2 мс со сглаживанием ×4; каждый занятый слой платит её заново.

На этом GPU время растёт примерно как 0.85 мс + 2.1 мс на миллион единиц стоимости, поэтому бюджет 450k — около 1.8 мс. На дискретных GPU бюджет можно поднять в несколько раз.

## Ограничения

- Авто-масштаб оценивает объём работы, а не время: бюджет под конкретное железо подбирается бенчмарком из пакета площадки.
- Scissor опирается на то, что прямоугольник задаётся от нижнего края render texture. Если у края кадра свечение обрезается, выключите `scissor`.
- В режиме `Object` паттерн поворачивается только вокруг оси взгляда; вращение объекта в глубину сдвигает его по экрану. Для полного прилипания — `SurfaceObject`.
- Прозрачные объекты не пишут глубину, поэтому перекрытие ими не определяется.
- Переход между обычным стилем и прозрачным: на всё время перехода объект рисуется проходом прозрачности (при `objectColor = Simple` — с упрощённым освещением), поэтому в конце возможен небольшой скачок освещения.
- Не больше 63 подсветок одновременно. Кадр не больше 4095 px по стороне.

## Тесты

EditMode-тесты в `Tests/Editor`: хэндлы и их версии, владение общими рендерерами, fade, лимит записей, выбор масштаба по бюджету. Запуск: Window → General → Test Runner → EditMode. В проекте пакет должен быть указан в `testables` в `Packages/manifest.json`.

## Дорожная карта

1. WebGL2: билд, замеры, подбор бюджета.
2. Rendering Layers как второй источник подсветки для большого числа объектов.
3. Подсветка только в выбранных камерах, настройки на камеру.
4. `SpriteRenderer` и 2D.
5. Поддержка кадров больше 4095 px.
